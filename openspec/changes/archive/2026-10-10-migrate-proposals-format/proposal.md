# Proposal

## Why

The `structuring_proposals.json` files generated by the AI pipeline use the old schema format (`attackType`, `appliedTo` at ability level, old `MortalWoundsEffect` fields). After the `restructure-rules-system` and `dice-notation-input` changes, the app's schema expects `phase`, per-effect `appliedTo`, and the new 3-field mortal wounds model with dice notation. Importing the old-format proposals crashes the app. Additionally, the legacy guard `if`s added to `ProcessUnitView.tsx` should be removed once data is clean.

## What Changes

- **New Python migration script** (`data/migrate_proposals.py`): transforms `structuring_proposals.json` to the current schema format. One-shot, idempotent. Transformations:
  - `attackType` → `phase` on each structured ability (value mapping: `ANY`→`ANY`, `SHOOTING`→`SHOOTING`, `FIGHT`→`FIGHT`)
  - Move `appliedTo` from ability level to each effect (default `SelfModel` if absent on both)
  - Remove ability-level `appliedTo`
  - Mortal wounds effects with `gameEvent: "onDestroyed"` (Deadly Demise): convert entire ability to `category: "OTHER"` with text from `originalText` or a generated description
  - Remaining mortal wounds effects: migrate `amount`/`preRoll`/`gameEvent`/`targetScope` → `unitType`/`hits`/`resolution`/`damagePerSuccess` using dice notation strings
  - Remove `amountByKeyword` (replaced by multiple effects per unit type — not auto-migrated, user handles manually if needed)
- **Remove legacy guards** from `ProcessUnitView.tsx`: remove the `if (!effect.resolution || !effect.hits)` check and the auto-migration in the `EffectFields` mortalWounds case, since all data will be in the correct format after migration
- **Re-run migration** on `space-marines/structuring_proposals.json` and verify the output
